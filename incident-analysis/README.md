# VTA・なぜなぜ分析ボード

事故やヒヤリハットの再発防止検討を、ヒューマンファクターの理論に沿って進めるための単一HTMLツール。
事故の種類を問わず、ヒューマンファクターの知識がない人でも使えるようにしている。

- 事故の種類ごとのテンプレート（車両、現場活動・作業、訓練、資機材、事務・情報、その他）でレーンを用意する
- 画面では日常の言葉を使い、専門用語は括弧で添える（例：「ここで止められた点（排除ノード）」）
- 各画面に「この画面でやること」を表示する
- なぜなぜでは、6つの観点ごとの質問と、エラーの種類を見分ける手順を出す
- 対策では、要因の観点とエラーの種類から対策の候補を出す
- 記入例：車両の横転事故、メールの誤送信

## 工程

1. 事案概要：事実だけを記録する
2. VTA：行為者・要素ごとのレーンに時系列でノードを置き、変動要因と排除ノードを決める
3. なぜなぜ：排除ノード・変動要因ごとに要因を掘り下げ、m-SHELLとエラーの型（Reason）で分類する
4. 要因整理：m-SHELL図、エラー型の集計、スイスチーズモデル、根本要因の一覧
5. 対策：河野の「エラー対策の発想手順」11項目と対策の階層、効果×実現性で優先度を付ける
6. 報告書：入力内容から報告書の下書きテキストを作る

「注意不足」「確認不足」などで止まった要因、注意喚起だけの対策には警告を出す。

## 使い方

`index.html` をブラウザで開く。入力はブラウザの localStorage に自動保存される。
共有や別端末への移動は「データの保存・読込」からJSONで行う。

## データ構造（アプリ化の土台）

```
meta      事案情報
lanes     [{id, name}]                         VTAのレーン
nodes     [{id, lane, seq, time, kind, text, variation, elim, note}]
edges     [{from, to}]                         ノード間の因果
whys      [{id, nodeId, parentId, text, shell, err}]   なぜなぜの木（parentId=null が1段目）
measures  [{id, whyId, text, kono, level, eff, feas, owner, due}]
```

アプリ化するときは、このJSONをそのままサーバー側のスキーマにし、複数人での同時編集、
事案間での根本要因・対策の横断集計、写真・ドラレコ等の証拠添付を加える想定。
